# 交点 CycleFlow

西南交通大学犀浦校区周边共享单车智能调度系统，毕业设计第一版原型。

**Spring Boot 4.1.1 / Java 21 + Vue 3 / Vite + H2 本地文件数据库。**

## 启动

环境：Java 21+、Maven 3.9+、Node.js 22.12+（或支持当前 Vite 的更新版本）。首次运行需要联网安装公开依赖。

```bash
./scripts/start.sh
```

打开 <http://127.0.0.1:8080>（运营控制台）；用户端在 <http://127.0.0.1:8080/rider>。Spring Boot 同时提供前端页面与 API，不需要单独安装数据库。服务默认只监听本机。已有程序占用端口时，可使用 `PORT=8081 ./scripts/start.sh`。

启动脚本使用项目内 `.m2/` 和 `.npm-cache/` 缓存依赖，均不进入 Git。构建后的可执行文件是 `backend/target/cycle-dispatch-0.1.0.jar`。

开发前端：先启动后端，再在 `frontend` 目录运行 `npm run dev`，访问 <http://127.0.0.1:5173>；开发代理默认后端端口为 8080。

地图默认使用高德 JS API。在 `frontend/.env.local`（已忽略，不会提交）配置：

```bash
VITE_AMAP_KEY=你的Web端(JS API)Key
VITE_AMAP_SECURITY_CODE=你的安全密钥
```

未配置或加载失败时会自动回退到 OpenStreetMap（优先 OSM Germany，再回退 Esri）。高德坐标会从 WGS-84 转为 GCJ-02，标记位置与公开坐标一致。若 Key 配置了域名白名单，需加入 `127.0.0.1`、`localhost` 以及实际的 Cloud Studio 预览域名；云端构建时在环境中设置同名变量即可，不要提交 `.env.local`。

道路距离矩阵使用高德 **Web 服务** Key，放在项目根目录 `.env`（已忽略，不会提交）：

```bash
AMAP_WEB_KEY=你的Web服务Key
```

`scripts/start.sh` 会自动加载该文件。未配置或接口失败时，系统回退到模拟网格距离；道路矩阵可在页面手动刷新。

### Cloud Studio 运行

工作区需要 Java 21、Maven 3.9、Node.js 22.12 及 npm。安装好后，在 Cloud Studio 编辑器顶部点击「运行」；项目中的 [`.vscode/preview.yml`](.vscode/preview.yml) 会执行 `scripts/start-cloud.sh`，构建前后端并开放 8080 端口。首次构建需要下载依赖，等待终端出现 `Tomcat started on port 8080` 后，在端口面板点击「查看预览」。也可以在云端终端运行 `bash scripts/start-cloud.sh`。

云端启动脚本仅在 Cloud Studio 进程内把监听地址设为 `0.0.0.0`，以便预览访问；本地 `./scripts/start.sh` 仍只监听本机。云端与本地的 H2 数据各自独立。

## 已实现

- 骑行赚奖励（C 端，独立入口 `/rider`）：普通用户视角，从富余站点取车、骑到缺车站点，完成悬赏后奖励到账；累计收益与历史记录在页面展示。控制台侧栏的「骑行赚奖励」会在新标签打开该页面。
- 运营总览：一行状态摘要、高德地图（可回退 OpenStreetMap）真实街道底图、补车优先级；场景切换、时钟与播放收进「演示控制」弹窗。
- 停车区域：真实地图选点联动库存详情与预测入口；支持搜索、类型筛选、修改名称、停车容量及安全库存，保存至后端。窄屏下区域表格改为可直接操作的卡片。
- 需求预测：按场景规则计算未来借还量、两小时曲线和分时段供需余额。
- 智能调度：缺口优先、就近匹配、每车载量 20 辆、两辆运输车；每辆车最多 6 个取/送停靠点，支持先取多单再送（在途不超过 20 辆），OR-Tools 在容量约束下规划两车路径与站序（失败时回退就近排序），生成、取消、逐站推进；送达时限按区域类型（轨道 45 / 校门 60 / 其他 75 分钟），赶不上的单会被放弃。路线优先调用高德 Driving 插件沿道路绘制；任务里程和时长来自道路距离矩阵，失败时回退为直线示意和网格估算。
- 道路距离矩阵：启动时抓取 12×12 区域间高德驾车距离和时长，调度与仿真实验共用同一份数据；可在页面手动刷新，矩阵未就绪时回退网格估算。
- 搬运播放：播放时按分钟连续推进（约 260ms 一分钟），「+5 分钟」按钮仍按 5 分钟一步；取车后计为运输中，到达后增加目的地库存。
- 仿真实验：不调度、阈值就近、预测优先三种策略；同种子生成相同的 1,260 次请求，回放 180 分钟，结果可导出 CSV。
- 路径对比：在工作日早高峰、晚高峰、周末三个场景，各按库存 ±5% 取三个样本，比较「贪心串行」与「OR-Tools 取送路径」的平均总里程、范围、用时和里程变化；结果以分组柱状图展示并支持导出 CSV，便于量化求解器收益。
- 任务记录：完整任务流水、状态筛选与搜索、生成原因、逐任务 CSV 导出。
- 多种子对比：1/3/5/10 个连续种子重复回放，展示均值、波动范围与逐种子成功率。
- 调度解释：生成任务时记录目的缺口、源区域可调出量与就近匹配原因；调度页汇总剩余缺口。
- 场景切换：工作日早高峰、晚高峰、周末；重置前说明清除范围。
- 响应式界面、键盘操作、加载／错误／空状态、数据与模型说明。

## 五分钟演示

1. 从运营总览查看一行状态摘要和补车优先级，点击地图点位查看库存；需要切换场景时打开「演示控制」。
2. 进入停车区域，搜索“西门”，编辑安全库存并保存。
3. 打开需求预测，切换不同区域，查看预期借还趋势；分时段明细按需展开。
4. 生成调度方案，执行任务，在调度页点击“播放”或“+5 分钟”。观察源库存、在途库存、目的库存变化，以及总量始终为 500。
5. 完成或取消全部任务后，进入仿真实验，运行并导出 CSV；逐种子明细按需展开。
6. 刷新验证状态保留；如需回到初始场景，在「演示控制」或调度页重置。

## 数据与算法边界

这是可运行的工程原型，**不使用当地真实车辆、订单或 GPS 数据**。底图默认来自高德地图，需要联网加载；未配置 Key、Key 失效或加载失败时回退到 OpenStreetMap（OSM Germany → Esri World Street Map）。12 个停车标记是候选地点／示范区域，未经现场核验。兴业北街站和犀浦站的公开坐标只作为接驳区域的定位参考，不代表站口旁已有合法停车位。容量、库存、需求与时间均为模拟参数。

地图支持缩放、拖动、选点和恢复视野。绿色路线优先按高德驾车规划沿道路绘制；调度任务和仿真实验统一读取 12×12 道路距离矩阵，矩阵未就绪或接口失败时回退为起终点直线和模拟网格估算。距离测量使用驾车模式并考虑实时路况，矩阵会记录更新时间，不是固定不变的道路数据；路线几何与矩阵时长也可能因策略或路况略有差异。地图服务及点位来源说明见 [docs/真实地图接入.md](docs/真实地图接入.md)。

需求预测目前为规则模型，没有训练机器学习模型。调度把每辆车组织成最多 6 个停靠点的取送行程（多点取送 + 载量耦合）：候选搬运对仍按「缺口优先 + 就近匹配」挑选，再由 OR-Tools 在 20 辆容量约束下分配两车并排序，目标包含载运行驶与站间空驶；送达时限在排程后用于过滤超时单，不参与目标函数；候选生成仍是启发式，不能称为全局最优。运输车假定在取车点就近待命，任务里程与时长取 12×12 道路矩阵（矩阵未就绪时回退网格估算），站间空驶已计入下一站时长；首站取车前的调车空驶仍未计入。

工作台时钟只推进搬运任务，不自动生成骑行订单；借还事件在独立仿真实验中发生。成功借车才生成还车；目的地暂满时车辆延后归还。实验结束时在途单车仍计入总量。实验基于当前地面库存，存在待执行或在途任务时禁止开始实验。多种子对比只改变请求序列种子，初始库存、策略参数和运输资源保持一致。

缺口会扣除已经安排的调入量；只有待执行任务能够取消；容量不能低于现有库存加已安排调入量。业务修改通过串行事务完成，以保证本地单用户原型的一致性。

## 数据存储

默认数据位置为 `backend/data/`（从启动脚本运行时）。刷新或重启保留区域和任务，重置演示会清除这些修改。此目录不进入 Git。请先停止程序再备份数据库文件。

本地演示使用 H2 的 MySQL 兼容模式。依赖已包含 MySQL 驱动，可通过 `DB_URL`、`DB_USER`、`DB_PASSWORD` 接入独立测试库；本版尚未验证 MySQL 实例，也未接入 MyBatis-Plus。不要在命令或源码里写入真实数据库密码。MySQL、MyBatis-Plus、多点路线优化和正式预测模型属于后续版本工作。
