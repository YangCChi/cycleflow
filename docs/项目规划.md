# 共享单车智能调度系统：犀浦校区周边毕业设计方案

更新日期：2026-10-09。当前阶段为需求分析与规划，尚未开发或接入真实运营数据。

## 已确认与待确定

- 已确认：毕业设计／课程项目，需要可演示、可答辩。
- 已确认：核心业务后端使用 Spring Boot。
- 已确认：研究地区为西南交通大学犀浦校区附近。
- 下文中的规模、前端、算法、地图服务和时间参数均为建议，尚未由用户逐项确认。
- 待确定：截止时间、学校对算法与技术版本的要求、是否已有借还记录、是否纳入校园内部。

## 题目与目标

建议题目：《基于 Spring Boot 的共享单车智能调度系统设计与实现——以西南交通大学犀浦校区周边为例》。若学校更强调算法，可将主标题改为《融合需求预测与路径优化的共享单车调度系统设计与实现》。

目标：在运输车容量和停车区域容量限制下，根据未来借还需求生成搬运数量与路线，通过仿真比较借车成功率、缺车时长和调度成本。

## 地理与业务范围

首版建议覆盖校门外停车区域、轨道交通接驳区域以及周边住宅和商业区域。通过地图圈定实际服务边界，初期按校区周边约 2～3 公里搜索候选点，再按道路可达性筛选，不能把圆形距离直接当作骑行范围。

学校官网确认犀浦校区地址为成都市郫都区犀安路 999 号。学校来校指南列出了犀浦站和兴业北街站的接驳方式，因此可将其周边列为候选调查区域。本文未核实具体停车线、停车容量、出入口坐标或实时车辆数量；交通站点不自动等同于共享单车停车点。

建议先选择 20～30 个停车区域、配置 500 辆模拟单车和 2 辆运输车。单车属于同一个模拟运营方。实际数量可调整，不代表本地运营规模。

校园内部作为扩展项：纳入时单独配置校门通行、单车运营范围和运输车通行规则，不默认校内外车辆可以自由互调。首版不涉及支付与智能锁接入。

候选区域类型与仿真假设：

| 区域类型 | 候选位置 | 需要验证的需求假设 |
| --- | --- | --- |
| 校门接驳 | 犀浦校区校门外停车区域 | 上下课、返校时段出现集中借还 |
| 轨道接驳 | 犀浦站、兴业北街站周边 | 通勤与学生出行造成方向性供需差异 |
| 居住区域 | 服务边界内住宅小区外停车区域 | 早晚高峰借还方向存在差异 |
| 商业区域 | 服务边界内餐饮、购物区域 | 午间、晚间与周末需求可能增加 |

这些需求模式用于设计实验，尚非实测结论。具体区域名称、坐标、容量和开放条件应逐点核验。

## 技术方案

| 层次 | 建议技术 | 职责 |
| --- | --- | --- |
| 前端 | Vue 3、Element Plus、ECharts | 管理页面、预测曲线、实验结果 |
| 地图 | 高德地图 JS API 与路径服务 | 底图、区域标注、道路路线 |
| 后端 | Spring Boot、Java、Maven | 业务接口、库存事务、调度流程、仿真 |
| 数据访问 | MyBatis-Plus、MySQL | 业务数据、模型输入、实验记录 |
| 优化 | OR-Tools Java | 搬运分配、取送路线和载量约束 |
| 预测 | Java 实现同周期统计与近期趋势预测；按论文要求扩展回归模型 | 预测分区域借出量与归还量 |

首版采用单体后端，预测与优化模块通过内部接口隔离。OR-Tools 官方提供 Java Maven 包，使用 Spring Boot 不意味着必须引入 Python 服务。具体 Spring Boot、JDK 与 MyBatis-Plus 版本在初始化项目时按兼容性锁定。

地图平台提供路线能力，车辆库存与借还记录需要单独的数据来源。地图接口需申请对应 Key，并按账号实际权限、额度使用。运输车使用适合车辆类型的道路时间和通行约束，骑行仿真使用骑行时间，不能共用直线距离冒充道路路线。地图暂不可用时可使用明确标为模拟路网的演示场景。

## 页面与模块

1. 运营总览：地图、区域库存、缺车与拥挤预警、数据时间、当前仿真时间。
2. 区域与车辆：停车区域、区域容量、单车状态、运输车载量与起点。
3. 数据与预测：CSV 导入、数据检查、借还趋势、未来各时段预测、预测误差。
4. 调度中心：调出与调入数量、运输路线、到达时间、分配原因、未满足需求。
5. 任务记录：待执行、执行中、已完成、异常、已取消；查看实际搬运数量与时间。
6. 仿真实验：场景选择、播放速度、重置、策略对比、结果导出。

首版一个管理端即可操作仿真任务，不先增加多角色权限体系。

后端建议按 region、bike、trip、forecast、dispatch、simulation、report 划分业务模块。核心数据对象为停车区域、单车、库存快照、借还请求与结果、运输车辆、需求预测、调度计划与任务、实验运行与指标。保存请求失败记录，才能计算仿真借车成功率。

## 预测与调度流程

1. 读取当前可用库存、近期借还记录及正在执行的搬运任务。
2. 按 15 分钟时间粒度，预测未来 30～60 分钟的借出与归还量。时间参数可配置。
3. 结合安全库存与停车容量，识别缺车和可调出区域。逐时段检查库存，不能只检查预测窗口末尾。
4. 分配区域之间的搬运数量，再为运输车生成取送路线。若路线不可执行，则调整搬运任务数量或优先级。
5. 展示每个任务的原因，例如预计缺口、可调出余量、行程和运输车剩余载量。
6. 模拟车辆出发、取车、运输、卸车，按实际事件更新时间与库存。
7. 每隔 15 分钟仿真时间滚动规划，固定已执行部分，考虑在途任务，避免重复调车。

第一版预测使用历史同星期同时段均值；后续加入近期趋势或回归模型，并与基线比较。预测模型只能使用预测时刻已知的信息。

调度策略至少包括：不调度、库存阈值加就近调车、预测加优化调度。调度优化需满足源区域库存、目标区域停车容量、运输车逐段载量、先取后送及行驶与装卸时间等约束。对无法满足的需求返回缺口及原因；对求解超时设置确定的回退策略。

库存事件应以事务更新。生成计划不直接改变库存，取车后单车进入运输中，送达后才成为目的区域可用车辆。首版可采用起终点都在服务区内的封闭仿真，验证地面车辆、骑行车辆、运输车辆和故障车辆的总量守恒；后续加入跨边界流入流出时必须单独记账。

## 数据与实验

首版采用真实地理背景与明确标注的仿真运营数据。支持工作日早晚高峰、平峰、周末及突发需求；这些模式是待验证的情景假设。随机种子、初始库存、需求请求序列、模型参数和算法版本均随实验保存。

若能获取本地数据，可补充区域库存定时观察、短时借还流量统计与匿名化运营记录。单凭库存差分不能分别还原借出量、归还量和人工搬运量。短期采样可用于校准，但不能自动视作完整长期训练集。

公开的外地历史骑行数据可用于验证预测方法，其结果应作为独立数据集实验呈现，不能将外地站点和订单改名后声称为犀浦实测数据。历史成功订单不能完整体现因无车而放弃的需求。

实验指标：

- 借还量预测 MAE，并按时间顺序划分训练、验证、测试数据。
- 借车成功率：成功借车请求数／总借车请求数。
- 区域缺车时长与停车容量超限情况。
- 调度总里程、总耗时、搬运数量、求解时间。
- 可选消融实验：保持路线算法相同，仅更换预测方法，区分预测与路径优化的贡献。

所有策略共享相同初始库存、请求序列和运输资源；仿真还车应由实际成功借车产生，不能为失败借车凭空生成还车。使用多个日期或随机种子重复实验，报告均值与波动，不预设提升百分比。

## 实施顺序与验收

1. 明确服务边界与候选区域：产出经核验的区域表，并区分真实属性和模拟参数。
2. 实现基础管理与仿真：完成借还与搬运库存流转，验证非负库存、容量限制和车辆守恒。
3. 实现简单调度：完整演示从发现缺车到运输完成的过程。
4. 接入预测与优化：返回可执行路线、未满足需求与原因，验证超时回退和任务去重。
5. 完成多场景对比：固定种子复现，导出论文图表和实验原始结果。
6. 准备答辩演示：一键重置、加速播放、参数调整和完整演示脚本。

首版验收：可在犀浦校区周边地理背景中完成一次可复现的调度仿真；库存和运输约束正确；三种策略的指标使用同一口径；地图、订单与预测结果的数据来源清晰。
